# Методология сборки делового аналитического отчёта в формате .docx

Документ-передача для другой ИИ-системы. Описывает подход, который использовался для генерации многостраничного аналитического Word-отчёта с корпоративным форматированием (навигация, KPI-карточки, callout-блоки, таблицы с заливкой, колонтитулы, система цитирования источников).

---

## 1. Философия подхода

**Принцип 1. Программная сборка, а не ручная разметка.** Документ собирается скриптом на Node.js с использованием библиотеки `docx` (docx-js). Никаких шаблонов `.docx` на диске — всё генерируется из кода. Это даёт: воспроизводимость, версионный контроль, лёгкие правки содержания, чистый XML без мусора от Word.

**Принцип 2. Модульность по разделам, а не по типам элементов.** Каждая крупная секция отчёта живёт в своей функции, возвращающей массив `Paragraph` объектов. Общие примитивы (заголовок, абзац, callout, таблица, KPI) вынесены в core-модуль. Сборщик (`main.js`) импортирует всё и склеивает в одну `Document`.

**Принцип 3. Дизайн-токены отделены от контента.** Цвета, отступы, размеры шрифтов заданы константами в одном месте. В тексте раздела пишется только смысл — оформление применяется хелперами. Изменить брендирование можно правкой 10 строк в палитре.

**Принцип 4. Контент и источники связаны системно.** Каждое числовое утверждение сопровождается ссылкой `[N]` на нумерованный список источников в конце. Это не декорация — это контракт на доверие читателя.

## 5. Каталог базовых примитивов

```javascript
P(textOrRuns, opts)
R(text, opts)
H1(text), H2(text), H3(text)
caption(text)
spacer(sizeDXA)
hr(color, size)

callout(title, lines, variant)  // "primary" (синий) или "gold"
kpiCard(value, label, sublabel)
kpiRow([card1, card2, card3])

dataTable(headers, rows, columnWidthsDXA)
bullet(textOrRuns, level)
numbered(textOrRuns, level)
```

### Ключевые детали

**Таблицы:** ширины в DXA. Сумма колонок = доступной ширине (US Letter 1440 DXA полях → 9360). Дублировать `columnWidths` и `width` в каждой ячейке.

**Callout:** Table с одной ячейкой, `ShadingType.CLEAR`, рамка слева 24–32 единицы в цвете акцента.

**KPI:** Table 3 ячейки. Цифра 48pt (size: 96), подпись мелкая, тонкие рамки в `primary`.

**Bullets/numbered:** через `numbering.config`, НЕ unicode `•` (ломает PDF).

## 6. Структура документа

```
1. Титульный лист          → titlePage()
   - Банер primary на всю ширину
   - Название, подзаголовок, дата, автор
   - PageBreak
   - Отдельная Section без колонтитулов

2. Аналитическое резюме    → executiveSummary()
   - H1
   - Вводный абзац с заметкой [N]
   - 2×3 KPI-карточек
   - H2 "Ключевые выводы"
   - 8 numbered выводов: H3 тезис + абзац со ссылками
   - Gold callout со стратегическим выводом
   - PageBreak

3. Оглавление              → tableOfContents() — статическое

4. Разделы 1..15           → sectionN_topic()
   Паттерн:
   - H1 "N. Название"
   - Вводный абзац с главным тезисом (жирный)
   - H2 подразделы
   - dataTable + caption("Таблица N. ... Источники: [x, y]")
   - kpiRow где уместно
   - callout в конце с выводом/рекомендацией
   - PageBreak

5. Список источников       → sourcesSection()
   - Нумерованный список
   - Методологическая заметка в callout
```

## 7. Сборщик main.js

**Section 1 (обложка):** без колонтитулов, только `titlePage()`.

**Section 2 (основная):** верхний колонтитул (название слева, золотая линия), нижний (автор слева, номер страницы справа), US Letter, поля 1440 DXA.

`styles.paragraphStyles` переопределяет Heading1/2/3 в primary-цвет, 32/26/22.

`numbering.config`: `"bullets"` (•, отступ 720) и `"numbers"` (%1.).

## 8. Система цитирования

Инлайн `[N]` или `[N, M]` в плоском тексте после утверждения с цифрой.

**Цитируется:**
- Все числовые показатели
- Главные тезисы разделов (жирные)
- Подписи таблиц

**Не цитируется:**
- Общие формулировки и выводы автора
- Переходы между мыслями
- Определения и классификации

Ссылки прямо в строке (`P("Премия 40% [12]")`), не через отдельный TextRun.

## 10. Подводные камни

1. `ShadingType.SOLID` не работает — только `CLEAR` с `fill` и `color: "auto"`.
2. `WidthType.PERCENTAGE` игнорируется — только DXA.
3. Списки через unicode ломают PDF — через `numbering.config`.
4. `characterSpacing` в TextRun не поддерживается (docx-js v9.6.1).
5. Вложенные таблицы в callout: явно задать `width` у обеих.
6. `PageBreak` только внутри `Paragraph`.
7. Цветные строки в ячейках — объектом `{text, bold, color}`, не строкой.
8. Валидация крупных doc через python-docx — 5–10 сек.
9. TOC статический. Автообновляемый = field-коды Word (сложнее).
10. Русские кавычки: `«»` и `„"`, не `""`.

## 11. Как расширять

**Новый раздел:**
1. Новая функция `sectionN_name()` по паттерну
2. Добавить в `module.exports`
3. Импорт в `main.js` → вставить в `children` Section 2 в нужном порядке
4. Обновить статический TOC в `tableOfContents()`
5. Пересобрать

**Поменять брендинг:**
1. Отредактировать `C = {...}`
2. Возможно шрифт в `main.js`
3. Пересобрать

**Новый источник:**
1. Добавить строку в `sources[]` — получит автономер
2. В тексте `[N]` где N = индекс+1
3. Пересобрать

---

## 12. Три правила

1. У каждой цифры есть источник.
2. У каждого раздела есть главный тезис и вывод.
3. Оформление подчинено смыслу, а не наоборот.
