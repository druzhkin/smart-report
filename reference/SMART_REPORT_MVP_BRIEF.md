# Smart Report MVP — Бриф по результатам брейншторма

**Дата:** 2026-04-14
**Статус:** Готов к разработке

---

## 1. Продукт в одном предложении

Персональный аналитический ассистент, который работает твоим методом: разворачивает вопрос в матрицу доменов, собирает проработанный материал по каждой ячейке, находит неожиданные связи между доменами — а ты дирижируешь процессом и делаешь выводы.

## 2. Для кого (конкретно)

Первый и пока единственный пользователь — ты. Аналитик в девелопменте и строительстве. Получаешь нетривиальные вопросы вроде «какие проблемы Москвы можно решить специализированным ЖК» или «какие мировые тренды повлияют на жилое строительство». Ответа в Google нет — нужна декомпозиция, поиск по множеству доменов, выстраивание логических цепочек, фильтрация банальностей.

## 3. Что ты делаешь сейчас (и что болит)

Твой текущий workflow:

1. **Фрейм.** Раскладываешь вопрос в матрицу доменов и слоёв (демография, экономика, логистика... → внутри каждого: страна, город, человек, здоровье, деньги...). ~15 мин.
2. **Сбор.** Идёшь по ячейкам матрицы, собираешь тезисы через Perplexity. Замечаешь интересное — ныряешь в сторону. **Это часы рутины — главная боль.**
3. **Выстраивание логики.** Расставляешь тезисы в цепочки: A → B → C → вывод. Или граф: A + B = C. Где звена нет — возвращаешься в сбор.
4. **Фильтр банальности.** Спрашиваешь себя: это капитан очевидность? В чём ценность? Выкидываешь плоское.
5. **Самокритика.** Просишь LLM оценить критически, находит дыры, чинишь.
6. **Упаковка.** Word → Gamma → правки. Ещё часы механики.

Между шагами — постоянные петли: шаг 3 отправляет в шаг 2, шаг 5 отправляет в шаг 3.

**Ключевой инсайт:** Ценность создаётся на шагах 3–4 (логика + фильтр). Шаг 2 (сбор) — это рутина, которая отнимает 80% времени. MVP должен закрыть шаг 2 и частично шаг 1.

## 4. Что делает MVP

### Взаимодействие

- **Цель.** Ты вводишь вопрос своими словами.
- **Фрейм.** Система предлагает матрицу доменов и слоёв, ты редактируешь: убираешь, добавляешь, переставляешь. Утверждаешь.
- **Сбор.** Система уходит работать. По каждой ячейке — не карточки-тезисы, а **проработанный мини-отчёт**: что нашлось, как связано, конкретные цифры с источниками, где пробелы. Блоки появляются по мере готовности — ты видишь процесс в реальном времени.
- **Бисоциативный проход.** После сбора система сталкивает тезисы из разных доменов, ищет неожиданные пересечения через общие переменные. Выдаёт отдельный блок кросс-доменных связей.
- **Интерактивная петля.** Ты просматриваешь результат, говоришь «тут копай глубже», «добавь домен X», «свяжи вот это с вон тем». Система уходит за новой порцией.
- **Экспорт.** Когда хватит — одной кнопкой в Word/markdown.

### Что НЕ делает MVP

- Синтез и выстраивание цепочек (это пока ты)
- Фильтр банальности (пока ты)
- Красивые слайды и инфографику
- Мультиязычность (работает как есть)
- Evaluate-петли, двухфазный проход, бюджетирование по ячейкам (оптимизации — добавишь когда увидишь что ломается)

## 5. Архитектура (простая)

Четыре роли. Не больше.

### Planner
- **Вход:** цель пользователя
- **Выход:** матрица доменов и слоёв + конкретные поисковые задания для Scout'ов
- **Модель:** frontier (Opus / GPT-4o) — качество декомпозиции определяет всё
- **Когда работает:** в начале + после каждой команды пользователя «копай глубже / добавь домен»

### Scout
- **Вход:** конкретное задание от Planner'а (ячейка + фокус + тип источников)
- **Выход:** сырые находки с источниками
- **Модель:** дешёвая (Haiku / Flash)
- **Особенность:** запускается пачками параллельно, 3–5 на ячейку с разных сторон
- **Ключевое:** качество поискового запроса — самый важный элемент. Planner формулирует конкретные задания, не абстрактные

### Analyst
- **Вход:** находки Scout'ов по одной ячейке
- **Выход:** проработанный блок (структура, выводы, цифры, источники, пробелы, ключевые сущности для графа)
- **Модель:** сильная (Sonnet / GPT-4o)
- **Особенность:** работает только с отфильтрованным материалом — фильтрация встроена в контракт (промпт), а не в отдельного агента

### Bisociator
- **Вход:** все блоки от Analyst'ов (точнее — извлечённые сущности и переменные)
- **Выход:** кросс-доменные связи с пометками: общая переменная, парадокс, неожиданное подтверждение
- **Модель:** frontier — нужно видеть всю картину
- **Теоретическая база:** бисоциация Кёстлера — поиск точек, где два домена неожиданно пересекаются

## 6. Поток данных

```
User: цель
  ↓
Planner: матрица + задания
  ↓ (user правит матрицу)
Scouts (×N параллельно): сырые находки
  ↓
Analysts (×M по ячейкам): проработанные блоки [стримятся в UI]
  ↓
Bisociator: кросс-доменные связи
  ↓
User: смотрит, направляет → Planner создаёт новые задания → цикл
  ↓ (когда хватит)
Formatter → Word/markdown
```

## 7. Теоретический фундамент (из исследования)

### Что забрать в промпты агентов

- **MECE-декомпозиция** (McKinsey). Planner строит матрицу так, чтобы домены не пересекались и покрывали всё пространство. LLM хорошо с этим справляется.

- **Analysis of Competing Hypotheses** (CIA). Когда есть противоречащие данные — не выбирать одно, а явно показать обе стороны. Встроить в промпт Analyst'а.

- **Key Assumptions Check** (CIA). Analyst в конце блока перечисляет: «неявные допущения, которые я делаю в этих выводах». Одна из самых надёжных способностей LLM.

- **Бисоциация Кёстлера.** Bisociator ищет не совпадения слов, а точки где одна переменная ведёт себя по-разному в разных доменах, или где вывод из домена A противоречит / неожиданно подтверждает вывод из домена B.

- **Серендипити: широта > глубины.** Учёные с широким кругозором лучше извлекают пользу из случайных находок. Система не должна предфильтровывать поле слишком рано.

### Что НЕ автоматизируется (пока)

- Серендипити — момент «о, это интересно». Система подсвечивает пересечения, но увидеть ценность — это ты.
- Фильтр банальности — LLM сама склонна к банальностям. Нужны проверяемые критерии, а не вкусовая оценка.
- Построение логических цепочек A → B → C — LLM может предложить, но качество суждения пока твоё.

## 8. Как оценивать качество

Единственный eval — **ты пользуешься каждый день и видишь, что ломается**. Конкретно:

- Блоки полезные или мусор?
- Scout'ы приносят релевантное или нерелевантное?
- Bisociator находит реальные связи или натянутые?
- Сколько времени сэкономлено vs. ручной процесс?

Когда увидишь конкретную проблему — добавляешь конкретное решение:
- Scout'ы тащат мусор → добавляешь Source Filter
- Блоки банальные → добавляешь критика с проверяемыми метриками
- Бисоциатор натягивает → ужесточаешь критерий общей переменной

## 9. Что НЕ делать (уроки из v2)

- **Не строить монолит.** Каждый агент — отдельный файл с отдельным промптом. Не 13k строк в одном файле.
- **Не хардкодить.** Никаких `confidence: 0.82`, никаких `if False:` блоков, никаких reference packs.
- **Не строить release gate, который блокирует всё.** Система отдаёт лучшее из того что есть + честные пометки о пробелах.
- **Не строить evaluate-петли до реального использования.** Это оптимизация, не фундамент.
- **Не целиться в универсальность.** Первый домен — девелопмент и строительство. Расширение — потом.

## 10. Стек (минимальный)

- **Backend:** Python, FastAPI, async. Простой оркестратор, не LangGraph.
- **Агенты:** набор async-функций с промптами. Каждый агент = промпт + модель + тулзы.
- **Поиск:** Perplexity API (на старте). Потом — Jina, Semantic Scholar, другие.
- **Frontend:** SSE-стриминг блоков по мере готовности. Минимальный UI: ввод цели, редактор матрицы, список блоков, кнопка «копай глубже», экспорт.
- **Промпты:** отдельные .md файлы (program.md-паттерн Карпати). Итерируешь промпты, не код.
- **Деплой:** Railway, один сервис.

## 11. Первый шаг

Начать с **самого рискованного элемента — качества поисковых запросов Scout'ов**. Взять один реальный вопрос из работы, руками написать 5 поисковых заданий, прогнать через Perplexity, оценить результат. Если результат хороший — автоматизировать. Если плохой — итерировать формулировки заданий до тех пор, пока не заработает. Только потом строить остальное.

## 12. Бэклог оптимизаций (не трогать до реального использования)

- Source Filter (отдельный агент фильтрации)
- Block Evaluator с числовыми метриками
- Двухфазный проход (быстрый скан → бюджетирование)
- Инкрементальный Bisociator (граф сущностей)
- Нормализация сущностей
- Построение цепочек логики (A → B → C)
- Детекция «нет данных» (2 пустых витка → стоп)
- DOCX с деловым форматированием
- Слайды (Gamma / PowerPoint)
