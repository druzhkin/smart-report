# Onepager: Smart Report MVP

*Технический и экономический обзор · 24 апреля 2026*

## 1. Обзор

- **Название:** Smart Report MVP (v3 → v4.5)
- **Что делает:** превращает нетривиальный аналитический вопрос в полноценный структурированный отчёт: разворачивает запрос в матрицу доменов, собирает данные из внешних источников, прогоняет их через цепочку ролей (Planner → Scout → Analyst → Bisociator; в v4.5 — Intake → Analyzer → Synthesizer → Critic) и выдаёт финальный документ с источниками и бисоциативными связями. На выходе — отчёт в DOCX, PPTX, Markdown и JSON.
- **Целевая аудитория / use case:** аналитик девелопмента и строительства, который получает вопросы уровня «какие мировые тренды повлияют на жилое строительство» или «что определяет успех девелопера в бизнес-сегменте Москвы». Пользователь задаёт вопрос, редактирует предложенную матрицу, получает проработанные блоки по ячейкам и пакет экспорта.
- **Стадия:** MVP, активная разработка на ветке v4.5 (семантический слой: цитируемость, сохранение фактов, language-lint, consistency-critic). Прод-деплой v3 не настроен, прежняя продовая v2 не используется. Есть суита из 218 автотестов на pytest (217 зелёных). Выделенного CI/CD пока нет.

## 2. Технические решения

### 2.1 Основные модули

| Модуль | Назначение | Технология / фреймворк |
|---|---|---|
| HTTP API | REST + long-poll/SSE, запуск сессий и экспорт отчётов | Python 3.11, FastAPI, uvicorn |
| CLI | Запуск пайплайна из командной строки, dry-run на заглушках | Python, Click |
| Оркестратор v3 | Асинхронный пайплайн Planner → Scout → Analyst → Bisociator | Python asyncio |
| Оркестратор v4 | Трёхшаговый сценарий generate-prompt → analyze → synthesize с паузами на ручной upload | Python asyncio |
| Семантический слой v4.5 | Intake (нормализация отчётов), Analyzer, Synthesizer, Critic, data-audit, language-lint, bibliography | Python, Pydantic v2 |
| LLM-клиент | Унифицированный async-вызов моделей с логированием и подсчётом стоимости | httpx |
| Retrieval | Поисковые запросы и целевой scrape страниц | httpx |
| Экспортёры | DOCX с KPI-блоками и нумерованными цитатами, PPTX, Markdown, JSON, HTML-onepager | Node.js 22 + docx-js (через subprocess), matplotlib для графиков |
| Промпты | Редактируемые промпты ролей в виде отдельных markdown-файлов | plain markdown |

### 2.2 Внешние сервисы и API

| Сервис | Для чего используется |
|---|---|
| OpenRouter | Единая точка входа к LLM: Claude Opus 4.7, Sonnet 4.6, Haiku 4.5, GPT-4o |
| Perplexity (sonar-pro) | Поиск и retrieval с источниками для Scout-роли |
| Jina Reader | Бесплатный scrape отдельных URL с JS-рендерингом (ЕРЗ, целевые страницы) |
| Deep-Research инструменты | Внешние агенты (Perplexity DR, OpenAI DR, Claude Research), в которые аналитик вручную вставляет сгенерированный промпт и возвращает markdown-отчёт в v4 |

### 2.4 Схема архитектуры

**Внутренние компоненты (то, что крутится в нашем деплое):**
- FastAPI-сервер — REST API и канал прогресса (SSE + long-poll)
- CLI — отдельный entrypoint на том же ядре
- Оркестраторы v3 и v4 — async-пайплайны, которые вызывают роли и внешние сервисы
- Node.js DOCX-рендерер — дочерний процесс, получает JSON, возвращает готовый документ Word
- Chart-рендерер — matplotlib, генерирует PNG-графики для вставки в DOCX
- In-memory session store — сессии v4 и jobs v3 живут в памяти процесса API
- Disk artefacts store — локальный каталог с артефактами прогонов: исходные ответы моделей, промпты, markdown, DOCX, PNG-графики и JSONL-лог LLM-вызовов
- Frontend — отдельный репозиторий, Next.js-приложение с чат-интерфейсом v4 и legacy-страницами v3

**Внешние сервисы (сгруппированные по функции):**
- LLM: OpenRouter (Claude Opus 4.7, Sonnet 4.6, Haiku 4.5, GPT-4o)
- Search / retrieval: Perplexity (sonar-pro)
- Web scraping: Jina Reader
- Deep Research (manual loop): Perplexity DR, OpenAI DR, Claude Research

**Основные потоки данных:**
- Браузер → FastAPI: HTTP (создание сессии, запуск шагов, экспорт)
- FastAPI → браузер: long-poll и SSE для стрима событий пайплайна
- FastAPI → оркестратор: in-process async-вызовы
- Оркестратор → OpenRouter: HTTPS (chat completions для всех ролей LLM)
- Оркестратор → Perplexity: HTTPS (retrieval с источниками)
- Оркестратор → Jina Reader: HTTPS (точечный scrape страницы)
- Оркестратор → Node.js рендерер: subprocess с обменом через временные файлы
- Оркестратор → файловая система: запись артефактов прогона и JSONL-логов
- Аналитик ↔ Deep Research: ручной вынос промпта и загрузка markdown-отчёта через UI

## 4. Итого по экономике

- **Постоянные расходы в месяц:** пока отсутствуют в явном виде — v3 не задеплоен в прод, БД и объектное хранилище не используются, Jina Reader бесплатен. Когда будет активирован Railway-деплой, постоянная часть сведётся к тарифу одного контейнера (бэкенд) и, при необходимости, отдельного сервиса под фронтенд.
- **Переменные расходы — драйверы:**
  - объём текста, уходящего в LLM (длина исходников, число ячеек, число retry)
  - выбор модели на каждом шаге (Opus дороже Sonnet/Haiku/GPT-4o в разы)
  - число Perplexity-запросов на прогон
  - частота повторных прогонов Synthesizer и Critic при срабатывании data-audit или language-lint
  - трафик и минуты контейнера в Railway при активном деплое

## 5. Что создаёт переменную нагрузку на бюджет

Сценарии, при которых месячный счёт растёт быстрее всего:

- **Массовый прогон длинных Deep-Research-отчётов.** Каждый новый markdown-файл на 60–120 КБ заново проходит через Intake и Analyzer и раздувает токены OpenRouter — это основная статья.
- **Переключение на Opus-only конфигурацию.** UI-тумблер «опус везде» поднимает стоимость одного прогона примерно на 10–15% и делает счёт чувствительным к числу сессий.
- **Шумные исходники, провоцирующие retry.** Если Critic находит противоречия или language-lint ловит много нерусских токенов, Synthesizer запускается повторно — каждый retry оплачивается отдельно.
- **Расширение матрицы доменов или увеличение числа Scout-задач на ячейку.** Растёт и OpenRouter, и Perplexity одновременно.
- **Параллельные пользовательские сессии после деплоя.** FastAPI хранит сессии в памяти процесса, так что рост нагрузки означает либо более мощный контейнер Railway, либо горизонтальное масштабирование с внешним стором — и то и другое увеличивает постоянную часть счёта.
