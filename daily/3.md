## Что сделано

1. **`smart_report/domain_detector.py`** — extended with the domain
   routing layer:
   - `Backend` enum (`VALYU` | `PERPLEXITY_MANUAL`).
   - `ValyuCallSpec` dataclass — encodes the right
     `(search_type, fast_mode, category, relevance_threshold)`
     tuple per route. Bakes the A3 fix into the routing rule, not
     the client default.
   - `BackendPlan` — `(primary, fallback, valyu_spec)` triple per
     domain.
   - `BACKEND_PLAN_BY_DOMAIN` — registry covering all 6 QueryDomain
     values:
     * `RU_*` (RE / automotive / tech) → PERPLEXITY_MANUAL primary,
       no fallback (Day 1 capability map confirmed Valyu has no
       Russian sources).
     * `EU_REGULATORY` → VALYU primary with
       `("proprietary", fast_mode=False)`, PERPLEXITY_MANUAL fallback.
     * `GLOBAL_TECH` / `GENERIC` → PERPLEXITY_MANUAL primary,
       VALYU fallback with `("all", fast_mode=True)` for cheap
       acceleration.
   - `backend_plan_for(query)` convenience — detect domain + look up
     plan in one call.

2. **`smart_report/sources/orchestrator.py`** — new
   `SearchOrchestrator`:
   - `.search(query)` returns a `SearchOutcome(backend, domain,
     results, handoff_required, fallback_used, primary_error)`.
   - For `PERPLEXITY_MANUAL` routes: returns
     `handoff_required=True` with empty results — caller drives the
     v4 manual DR loop. We don't have an auto Perplexity client yet;
     this is the honest scope (and a future Perplexity client would
     drop in here without changing the orchestrator surface).
   - For `VALYU` routes: dispatches with the route's `ValyuCallSpec`
     kwargs.
   - Empty `VALYU` results OR `ValyuSearchError` → fall through to
     `plan.fallback` (if any) with `fallback_used=True`. The
     primary_error reason is preserved on the fallback outcome.
   - Defensive: blows up with a clear `RuntimeError` if a route
     would need Valyu but no client was injected; pure-manual routes
     work fine without a Valyu client.

3. **`smart_report/sources/__init__.py`** — re-exported
   `SearchOrchestrator` + `SearchOutcome`. Updated the package
   docstring to reflect the new dispatch surface.

4. **`tests/test_search_orchestrator.py`** (13 tests, all mock-only):
   - 6 routing-decision tests: EU_REG → proprietary+fast=False, RU_RE
     skips Valyu, RU_AUTO skips Valyu, GLOBAL_TECH primary=manual
     fallback=Valyu(fast/all), GENERIC same shape, every QueryDomain
     covered by a plan (catches future enum additions).
   - 7 dispatch tests: handoff for manual primary, EU_REG calls Valyu
     with the right kwargs, empty Valyu → manual fallback, Valyu raise
     → manual fallback, RU domains do NOT touch Valyu, no-Valyu-client
     OK for pure-manual route, no-Valyu-client raises clearly when
     route needs Valyu.

- **A3 risk now closed at the routing layer.** Tests prove that an
  EU_REGULATORY query forces `search_type="proprietary",
  fast_mode=False` — the Day 5 A/B run can't accidentally hit web
  search via the wrong default.

  Day 3). Total runtime 14.5s — orchestrator tests are <0.1s.
- **Manual Perplexity surfaced via sentinel** rather than a stub
  client. This was a judgment call: a stub Perplexity client would
  invite "the orchestrator works end-to-end" claims that aren't
  true. The sentinel makes the manual handoff visible to every
  caller; the v4 chat UI can branch on it, the eval harness can
  count it, and the future Perplexity client implements one
  adapter without touching dispatch.
